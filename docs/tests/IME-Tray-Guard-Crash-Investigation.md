## 已确认的直接崩溃路径

微软匹配PDB标识：`E15A88ED9599B347A0D2576C13287FC41`，DLL版本`10.0.26100.9711`。
证据：`build/ime-tray-guard/evidence/container-width-native-20261024-01/dump-symbolized.txt`及`dump-root-locals.txt`。

`AdviseVisualTreeChange → GiveRootsToCallback → Diagnostics::GetRuntimeElement → RoFailFastWithErrorContext`。
崩溃线程`0x6464`名为`MultitaskingView`，不是任务栏线程。反汇编显示`TryGetAsElement`失败后
带`0x8000ffff`触发FailFast。工作线程在等待全根节点重放，宽度写入仍为0。
这不是MinWidth写入崩溃，也不能靠工作线程try/catch捕获。小型转储不含对象堆，
尚不能确认具体是哪一个根对象及其分类失败原因；“重复附加”不能冒充全部根因。

## 失败对照与修复边界

| 隔离场景 | 结果 |
| --- | --- |
| 两活UI线程、动态节点、旧版两次附加 | 通过，未复现FailFast |
| 副UI线程退出后再次附加 | 旧版与COM封送修正版均卡在Attached；原始失败保留 |

| 单订阅、三次占位/恢复、副线程退出 | 3次写入、3次恢复、0恢复失败 |
| 常驻订阅、三次控制程序租约 | 首次attach，随后两次reuse_subscription，全部退出0 |
| 常驻订阅并反复开关 | 3次写入、3次恢复，隐藏时76 DIP，关闭时0/unset |
| 新界面租约正常40秒结束 | 越过初始30秒期限，最终1次写入/1次恢复 |
| 界面停止心跳 / 界面进程被结束 | 两项均恢复原始unset，未结束Explorer |

后三项证据在`build/ime-tray-guard/evidence/client-lease-01`。恢复测试不能并行启动：
控制程序有会话单实例锁。误并行的两次失败保留，串行重跑通过，不将测试编排冲突记成产品恢复失败。

实现采用每个Explorer进程一次诊断订阅；关闭仅恢复宽度和结束租约，不重复全根重放，
不强行卸载DLL。空闲时不设置宽度、无采样定时器，诊断回调连接保留至Explorer退出。
界面每250ms发送心跳，控制程序只把目标端期限续到约5秒后；界面心跳超过2秒或进程退出时停止。
控制程序本身停滞时目标端期限仍能到期。连续会话上限24小时，到期恢复并需手动重新启用。

### 代码审查记录

- 关闭恢复与诊断退订是不同动作；界面明确说明连接驻留，不能声称DLL已卸载。
- 控制程序使用窗口心跳续租，最长只提前约5秒，不能变为无限期宽度覆盖；首次附加期限单独保留。
- 常驻日志只在状态变化或每5秒记录一次，不持续导出完整节点树，防止磁盘无限快速增长。
- 单实例拒绝、原生显式开关、构建门禁和每Explorer单次首次附加仍保留。
- 尚未关闭的发布风险：首次附加根对象失败原因、布局环境变化适配、原生命中/菜单和多系统验收。
- 结论：仅交付明确标注限制的研究预览，不批准稳定发布或替换主程序。

当前结论：**该构建上的原生空位技术可行性已获得真实正反对照；不是跨系统稳定性完成证明。**
尚缺原生菜单/空白命中、单图标显隐、100次切换、第三方冲突、DPI/多屏、Explorer重建、Windows10和8小时耐久。
研究预览仅支持已测构建，未接入正式配置/主面板，不发布稳定功能。
