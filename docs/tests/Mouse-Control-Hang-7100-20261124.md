# 7.100 滚轮启用后卡住与退出不完成

## 现场

目标为 192.168.7.100（主机 ypy）的实际交互会话 2，程序路径为用户 Downloads/yakoye-release/WindowMark/WindowMark.exe，配置中 wheel_enabled=true、pointer_enabled=false。现有 SSH 免交互认证用于诊断，没有采集或输入密码。

旧进程 PID 8676 留有线程 2332。两次短暂暂停该线程读取上下文，指令地址均解析为 NtUserSendInput；读取后立即恢复线程。此处记录的是线程当前指令及栈内候选地址，不将扫描结果冒充完整符号化调用栈。证据保存在开发目录 build/evidence/remote-7100-hang-stack.json。

旧代码在 WH_MOUSE_LL 回调中直接同步 SendInput，且退出使用无界 join。这条路径存在输入钩子链重入和无法退出的风险。旧进程发出终止请求后 HasExited=true，但内核仍保留线程和映像锁；无法原位覆盖 EXE。旧映像已保留到历史目录，再放入修复 EXE。没有重启 Explorer、修改全局输入法配置或重启系统。

## 修复

- 普通及精细滚轮只限频，原样继续输入链；不再同步重发。
- 多格输入只在回调中投递线程消息，回调结束后再规范化发送；自己的重发标记直接通过。
- 丢弃超过 250 毫秒的待发输入；异步发送失败时解除监听并提示。
- 启动就绪等待 1500 毫秒，退出先标记停止、解除监听，再有界等待，期间处理同步消息。
- 极端情况下迟退出线程只引用共享状态，不保留 WinMouseControl 的 this 指针，避免销毁后访问。
- 新增模拟工作线程完全不返回的回归，验证停止操作有界、监听状态关闭、迟返回对象安全。

## 验证

本机 CTest 3/3 通过，包括输入方向、普通事件直接放行、多格排队决策、自身重发绕过和阻塞退出测试。

第一份诊断构建在 7.100 的真实交互会话两轮验证：

| 轮次 | PID | 主面板窗口消息响应 | 公开 CLI 正常退出 |
| --- | --- | --- | --- |
| 1 | 43804 | 通过 | 通过 |
| 2 | 23268 | 通过 | 通过 |

随后通过常驻 Explorer（父 PID 18564）重开进程 44828。验证由一次性交互任务运行公开 --panel/--quit 命令及只读 WM_NULL 查询完成，不模拟鼠标、不截图。后台 SSH 会话 0 无法读取会话 2 窗口，因此窗口响应查询专门在会话 2 执行。

最终干净提交构建及部署后的复测结果，保存在 build/evidence/remote-7100-final 和共享目录 share_chatgpt/WindowMark-debug-065。只有实际生成的结果文件代表最终复测完成，不以这段路径说明代替执行。

真实手机滚轮手感和每个菜单的实际鼠标点击仍需使用时确认；消息响应与 CLI 退出通过不等于硬件链路全覆盖。旧终止进程的内核记录若继续保留，不能把它当成新版本活跃实例。
