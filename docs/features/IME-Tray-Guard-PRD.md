# WindowMark：任务栏输入法占位保护（IME Tray Guard）

> 范围补充（用户于 2026-10-24 明确）：同时面向 Windows 10 和 Windows 11。
> 以下保留原始 v1.0 内容；其中仅写 Windows 11 的验收项须为 Windows 10 单独补证，不能推定互通。
> 显示补充（同日用户确认）：不补画图标。输入法不可用时只保留空槽，不绘制「中」「拼」或「无输入法」文字。
> 新增约束：WindowMark自己的通知图标被折叠到“^”后，占位仍须有效（进程仍运行）。
> 待评估候选：用户提出透明通知图标互补，以及借鉴PiInput通过TSF语言栏项目占位。
> 这两项作为技术候选评估，不代表已接受宽度不足、切换输入法、干扰原生项目或只在通知图标展开时有效。

## 1. 背景与问题

Windows 11 本地任务栏右侧会显示微软拼音相关的「中」和「拼」两个输入法状态图标。用户已经观察到：

- 切换到普通可输入文本的窗口时，两个图标正常出现；
- 聚焦 **Windows 远程桌面（mstsc/RDP）、VNC Viewer、MobaXterm** 时，两个图标可能同时消失；
- 恢复本地窗口时，图标重新出现；
- 这种显隐改变了任务栏系统托盘的总宽度，导致 Wi-Fi、音量、其他托盘图标左右移动；
- Windows「高级键盘设置」中，「允许我为每个应用窗口使用不同的输入法」与「使用桌面语言栏」原本均未勾选，问题仍然复现。

这是**系统托盘布局稳定性**问题；不能未经验证就认定是输入法服务故障，也不能把频繁重启 `ctfmon.exe` 当成永久修复。

## 2. 一句话需求

**无论切换到哪个窗口，输入法状态图标可以按 Windows 原有逻辑出现或消失，但其所在的任务栏空间不能跟着收缩或扩张，避免其他图标移动。**

实现的是 **固定槽位/固定布局**，不是伪造输入法状态，也不是强迫远程软件接受本地输入法。

### 2.1 显示规则

| 状态 | 「中」位置 | 「拼」位置 | 托盘其他图标 |
| --- | --- | --- | --- |
| 微软拼音正常显示两个图标 | 原生「中」 | 原生「拼」 | 不移动 |
| 切换到 RDP，两个都被隐藏 | 透明占位 | 透明占位 | 不移动 |
| 切换到 VNC Viewer / MobaXterm | 隐藏的槽位透明占位；仍显示的图标保留原状 | 同左 | 不移动 |
| 只剩下一个原生图标 | 原样显示/占位 | 原样显示/占位 | 不移动 |
| 返回支持文字输入的本地窗口 | 恢复实际原生图标 | 恢复实际原生图标 | 不移动 |
| 切换输入模式（中/英等） | 显示真实系统状态 | 显示真实系统状态 | 不移动 |
| 输入法被禁用、卸载或系统布局发生实质变化 | 允许安全退出本保护模式 | 不绘制假状态 | 不影响其他功能 |

**重要：** 缺失图标时应为**透明、不可点击的占位槽**；不可显示上一次缓存的「中/拼」，否则可能误导用户。图标存在时仍应保持原生鼠标点击、悬停、输入法菜单及键盘切换行为。

## 3. 范围和优先级

### P0：必须完成

1. 独立的「任务栏输入法占位保护」功能开关，默认**关闭**，启用前说明兼容性。
2. 在支持的 Windows 11 版本上，对**真实原生**输入法区域固定布局宽度；目标为两个独立槽位（不得使用两个额外的常驻托盘图标冒充原生槽位）。
3. 监测实际托盘/IME 元素显隐，不依赖 RDP、VNC Viewer、MobaXterm 的进程名作为唯一判断条件。
4. 单一图标消失和两个图标同时消失均能保留所需空间。
5. 关闭功能、退出 WindowMark 后恢复 Windows 原样；Explorer 重启、分辨率/DPI 变化后可安全重建。
6. 修改失败要快速**回退为系统默认行为**；不影响 WindowMark 的书签、边框、拖动、置顶、ClipKeeper。
7. 明确区分本机任务栏与远程电脑自己的任务栏：只保证 **WindowMark 所在 Windows 会话**，不声称直接修改远端桌面的托盘。

### P1：建议完成

1. 设置页提供状态：`已启用·保护生效` / `已启用·当前不兼容` / `已关闭` / `异常·已自动恢复`。
2. 自动检测系统版本、Explorer 版本、任务栏结构变化；兼容性检查不通过时不启用危险修改。
3. 支持主屏和副屏任务栏、不同缩放比例、横竖排列（具体支持矩阵以验证结果为准）。
4. 提供轻量诊断（系统版本、保护开关、当前原生图标数量/显隐、目标区域宽度、失败原因）；默认不记录输入文字。
5. 恢复机制复用现有 WindowMark 事件/看门狗基础设施，但不得因托盘异常持续重启 Explorer。

### P2：后续研究，不能冒充 P0 已实现

1. 非微软拼音及其他第三方输入法的兼容性。
2. 不同语言布局和超过两个 IME 系统指示器的动态槽位管理。
3. 对不兼容系统提供**可选**的自绘替代输入状态控件；其外观、状态来源、点击行为与真正原生图标可能不同，应单独说明、单独启用，且不可重复显示两套图标。

## 4. WindowMark 中的交互设计

### 4.1 主面板 / 设置

添加独立模块：**任务栏 → 输入法占位保护**。

建议文案：

- 开关：`固定输入法图标位置`
- 说明：`切换远程桌面或其他程序时，保留输入法图标原来的空间，避免任务栏图标左右跳动。`
- 状态：`保护生效` / `此 Windows 版本暂不支持` / `保护已暂停`
- 操作：`检测兼容性`、`恢复系统默认`、`导出诊断信息`

托盘右键菜单可放在「任务栏」子菜单下，不混入书签/窗口边框控制项。设置写入现有 `settings.conf`，不得覆盖用户之前的配置。

### 4.2 默认策略

- 安装/升级后默认关闭；
- 用户启用时先执行兼容性探测，再真正修改；
- 首次使用提供一次简洁风险说明；
- WindowMark 正常退出、系统关机和禁用功能时恢复；
- 检测到未知 Windows 任务栏结构时自动停用修改，并提示“当前版本暂不支持”。

## 5. 技术预研与实现约束

**先做可行性原型，证明原生槽位能被固定，再合并正式功能。不可直接承诺能改造所有 Windows 版本。**

### 5.1 原型要回答的问题

1. Windows 11 当前版本中「中」「拼」分别对应什么实际任务栏/输入法元素？其宿主、父容器、原始布局宽度分别是什么？
2. 消失时是仅图标 `Visibility=Collapsed`，还是其整个容器被卸载/销毁或重建？
3. 能否只在原生 XAML 任务栏容器上保存固定布局空间，例如适配地处理隐藏状态与测量宽度，而不干扰其他托盘区域？
4. 如何区分原生图标正常显示、被隐藏、输入法真正卸载等情况？
5. Explorer 任务栏被重建、会话锁定、显示器切换、DPI 改变时，如何可靠清理或重新附加？
6. Windows 更新导致 XAML 树变化时，如何安全识别“不兼容”并不进行修改？

### 5.2 两种可行性路线

- **A. 原生区域占位（首选，原型验证后决定是否发布）：** 根据实际系统任务栏 UI 树做最小必要的布局干预，保留系统原生图标及行为。可能需要 Explorer 进程内组件/注入技术，应隔离风险。
- **B. 替代控件（仅备选）：** 如果路线 A 在目标系统无法安全实现，可调研单独的常驻输入状态显示控件，但它不是“固定原生两个图标”，也可能需要处理原生图标重复显示的问题。没有确认用户接受该差异前，不作为 P0 的替代验收。

可参考 Windhawk 社区公开研究的 Windows 11 任务栏 XAML 元素与 IME 托盘区域，但需独立验证目标系统结构、兼容性和第三方代码许可证；不要直接复制不受控的 Hook。

### 5.3 安全红线

- 不得用反复终止/重启 `explorer.exe`、`ctfmon.exe` 的方式维持占位。
- 不得持续改写全局输入法设置、输入语言、键盘切换热键或服务启动类型。
- 不得侵入远程连接程序的数据流、截获按键、读取剪贴板或记录用户文本。
- 禁止固定屏幕坐标的透明悬浮窗伪装成真正任务栏槽位；不能遮挡原生菜单或鼠标交互。
- 不引入开机就自动注入的模块，除非用户启用且兼容性已确认。
- 不兼容、附加失败、崩溃重启频发时必须可自恢复、可禁用，且不让 Explorer 进入崩溃循环。
- 不要仅凭功能“看起来不跳了”就宣布可用；必须验证图标点击、状态与系统更新场景。

## 6. 状态机

`Disabled → Checking → Active → (Recovering | Unsupported | ErrorSafeDisabled)`

- `Disabled`：系统默认布局，无修改。
- `Checking`：检测环境和对应元素，未验证前不应用修改。
- `Active`：固定原生托盘输入区域布局。
- `Recovering`：Explorer 重建、DPI 变化等事件触发重新附加，失败则安全停用。
- `Unsupported`：系统构建/任务栏结构不匹配，不修改 Explorer。
- `ErrorSafeDisabled`：运行时异常，自动清理修改并禁用，记录错误信息。

回退路径必须可在 Windows 任务栏仍然可操作的情况下触发。

## 7. 测试计划与验收 Case

| ID | 场景 | 预期 |
| --- | --- | --- |
| IME-001 | 功能关闭，对比原始行为 | 不改变任何图标显示/点击规则 |
| IME-002 | 记事本/浏览器输入框之间切换 | 原生图标正确，非目标托盘图标位置固定 |
| IME-003 | 本地窗口 → Windows 远程桌面 → 本地窗口，连续 100 次 | 两个槽位始终存在，其他图标位置不移动 |
| IME-004 | 本地窗口 → VNC Viewer → 本地窗口，连续 100 次 | 同上 |
| IME-005 | 本地窗口 → MobaXterm → 本地窗口，连续 100 次 | 同上 |
| IME-006 | RDP 全屏/窗口化、断开/重连 | 本机任务栏无残留、无抖动 |
| IME-007 | 只隐藏「中」或只隐藏「拼」 | 仅目标图标变透明，不改变布局宽度 |
| IME-008 | 切换中/英、输入法候选菜单、左右键点击 | 原生功能正常，没有假状态 |
| IME-009 | 重启 Explorer、重新登录、睡眠唤醒 | 自动恢复或安全退出保护 |
| IME-010 | 双显示器，100%/125%/150% 缩放，主副屏变更 | 不错位、不遮挡；不支持的布局明确提示 |
| IME-011 | 全屏游戏、任务栏自动隐藏、弹出系统托盘菜单 | 不导致闪烁、抢焦点或异常弹出 |
| IME-012 | 关闭功能、退出/卸载 WindowMark | 恢复默认，绝不残留占位 |
| IME-013 | 未识别 Windows 构建、模拟 Hook 失败 | 不修改或自动回滚，不崩溃 |
| IME-014 | 同时启用 WindowMark 书签/边框/置顶/拖动/ClipKeeper | 互不影响 |
| IME-015 | 安装了第三方任务栏修改工具 | 检测到冲突则提示并安全停用 |
| IME-016 | 连续运行至少 8 小时、多轮窗口切换 | 无明显资源增长、无 Explorer 异常 |

**关键验收指标：**

- 在固定显示器、分辨率、缩放、任务栏配置下，切换窗口前后，**非输入法托盘图标的水平坐标变化应为 0 像素**（通过自动截图/实际控件边界对照验证）。
- 有图标时，继续使用原生图标；无图标时，保留不可交互的透明槽。
- 开关、重启、卸载均可恢复；Explorer 不崩溃，输入法不失效。
- 不支持的系统明确显示未生效，不得把“不兼容”伪装成“保护成功”。
- 所有测试要记录实际环境、步骤、结果、截图与缺陷链接；未执行的不标记“通过”。

## 9. 建议开发顺序（Codex 执行）

1. 阅读当前 WindowMark 架构、主面板、托盘菜单、配置与看门狗实现，确定最低耦合的接入位置。
2. 创建预研文档和运行环境检测/诊断原型；仅观察，不修改任务栏。
3. 在当前机器上验证「中」「拼」各自对应的任务栏结构和消失方式，保存技术证据。
4. 如果可行，做最小范围的原生占位 PoC；首先测试 RDP/VNC Viewer/MobaXterm 和恢复原状。
5. 将经过验证的实现整合成独立、可开关的 WindowMark 模块，默认关闭。
6. 补全 UI、配置持久化、异常回退、文档和回归测试。
7. 出具真实验收报告；不满足 P0 或安全红线则保留为实验功能，不发布为稳定功能。

**给 Codex 的总指令：** 不要把“隐藏图标”“增加两个假托盘图标”“启动 ctfmon.exe”“按程序名屏蔽输入法”当成需求完成。真正的 P0 是：原生图标正常工作，消失时原来那两个槽位仍保留宽度，其他任务栏图标不发生位置变化；若实现条件不具备，提交预研结论和可复现实验，不冒险修改 Explorer。
