# 输入法占位保护：实施计划与开发清单

更新：2026-10-25。当前开发 Windows 11；Windows 10 按用户最新要求暂停。

最新阶段：D 主程序集成已实现，默认关闭；当前开发和验收进度见
[主程序集成清单](IME-Tray-Guard-Integration.md)。下文保留前期研究记录，不等于最新交付状态。

## 目标与阶段门槛

原生「中」「拼」消失时保留真实布局槽，非 IME 托盘图标不移动；正常显示时保留原生行为。
用户最初要求不可交互的空槽，随后追加空位提示语；rc.3 在真实占位内显示可关闭的短句，不补画输入法图标、不拦截点击。
WindowMark自己的通知图标被系统折叠时仍须生效，不能依赖它在外侧可见。
早期附加异常已定位到全根重放FailFast；单订阅复用后，经用户授权在本机测得原生占位与恢复有效。
已有默认关闭的中文研究预览EXE，首次附加风险、Win10、原生点击、多屏和长期运行仍待验收。
不提供虚假的功能开关。交付升级候选版本号并安装供测试，不发布为稳定功能。
最初需求见同目录 PRD；用户随后明确追加 Windows 10 支持。

| 阶段 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| A 结构采证 | 只读 EXE、双击入口、环境与任务栏 JSONL、共享协作说明 | Win10/11 的实际显隐前后结构有可复核证据 |
| B 最小布局原型 | 独立、显式启动的实验程序及原值恢复记录 | 确认宿主及隐藏方式；仅操作匹配结构，证明占位与恢复 |
| C 可行性报告 | 平台分别给出可行/不可行/未验证及依据 | 向用户提交结果；未通过的平台不得标记支持 |
| D 正式集成 | 独立后端、默认关闭配置、主面板/托盘状态与恢复操作 | 兼容性探测通过才修改；不影响现有功能 |
| E 验收交付 | 自动化、真机、恢复与耐久报告；正式产物双归档 | P0 与安全项实际通过；不把采集成功视为保护成功 |
