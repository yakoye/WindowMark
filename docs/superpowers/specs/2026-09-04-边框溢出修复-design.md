# 边框溢出修复 — 设计

日期：2026-09-04
来源：使用者反馈「v0.4.5 的裁剪没解决问题」

---

## 现象

1. 全屏（最大化）时边框仍然溢出
2. 偶现：普通窗口的**右边和下面**溢出
3. **拉伸一下窗口就恢复正常**
4. 应用相关：Excel、360 浏览器会出现，WPS 不会

---

## 取证

从使用者录屏抽帧（`ffmpeg -vf fps=1`），逐帧找出红色边框的外接矩形：

- 画面 960 宽对应双屏 3840，边框右边界稳定在 **482 → 实际约 1928**
- 第一块屏右边界是 1920，**溢出约 8px**

8 正是本机实测的还原态内缩量（`GetWindowRect` 与 DWM 边界之差 `8,0,8,8`）。这把方向指
向了内缩量缓存。

另一份证据来自使用者截图：**红线穿过任务栏**。扫描当时屏幕上所有被描边的窗口，每一个的
边框底边都在 y=1023，而工作区底是 1020——所有窗口都多画了 3px 在任务栏上。

---

## 三处根因

### 一、底边夹错了参照物

`ClampBorderToMonitor` 只跟**监视器**矩形比。而最大化窗口的 DWM 边界等于**工作区**：

```
监视器  (0,0)-(1920,1080)
工作区  (0,0)-(1920,1020)      ← 任务栏占 60px
最大化窗口的 DWM 边界 = 工作区
```

底边的 gap 是 `1080 - 1020 = 60`，远大于 `reach = 3`，判据 `0 <= gap <= reach` 不成立，
于是**底边从来不夹**，边框画到 1023。

原 spec 写「底边落在任务栏区域，被任务栏遮住，无害」——**这个假设是错的**：边框窗口本身
带 `WS_EX_TOPMOST`，不会被任务栏遮住，那 3px 就画在任务栏上面。

**修法**：每条边分别判断，**工作区优先、监视器兜底**。

- 最大化 / 半屏吸附贴的是工作区，底边尤其如此
- 用户手动拖到盖住任务栏的窗口贴的是监视器；按工作区判断 gap 为负（−60），落到监视器
  这一档才夹得对

函数更名为 `ClampBorderToScreen`，多收一个 `workArea` 参数。

### 二、动画期间标定出的内缩量被当成可信值缓存

`FrameFor()` 把「窗口矩形与 DWM 边界之差」按窗口尺寸缓存。最大化和还原**都有动画**：
`GetWindowRect` 立刻返回终值，而 DWM 边界还在动画中间。

在那一刻标定出的内缩量是错的**但非零**，于是被这一句放行：

```cpp
if (!zero) return true;      // 只要非零就认为可信
```

缓存只在尺寸变化时重标定，而最大化之后尺寸不再变——**就一直错到用户拉伸窗口为止**。
这正好解释了现象 2 和 3：偶现（取决于 DWM 更新时机）、拉伸即恢复（尺寸变了触发重标定）。
也解释了现象 4：不同应用的窗口动画时长和 DWM 更新时机不同。

**修法**：加一条合理性检查。内缩量本机实测都是个位数（还原 `8,0,8,8`，最大化 `9,9,9,9`），
超过 **32** 只可能是读到了上一个状态的边界，不予缓存，下一次几何更新再试。

### 三、缓存键漏了最大化状态

缓存键是「窗口 + 宽 + 高」。把窗口手动拉到**正好等于工作区大小**再最大化，`GetWindowRect`
的尺寸不变，而内缩量从 `8,0,8,8` 变成 `9,9,9,9`——只比尺寸会认为不必重标定。

**修法**：`FrameInset` 加 `bool zoomed`，纳入缓存键。

## 附带修正：用 HWND 而不是算出来的矩形去问监视器

原实现：

```cpp
MonitorFromRect(&frameRect, MONITOR_DEFAULTTONEAREST)
```

理由写的是「不依赖那个 HWND 此刻是否还有效」。**这个理由站不住**：`model_.frame` 本身就是
从这个 HWND 算出来的，中间还隔着一层内缩量缓存。frame 一旦偏了，拿它去问监视器会**连屏都
选错**，于是夹到隔壁屏的边界上——那正是要修的毛病。

不能让修复本身依赖它要修的那个可疑输入。改用 `MonitorFromWindow(target, ...)`。

## 验证

**单测**（`TestBorderClamping`，全部新增或改写）：

| 用例 | 要点 |
|---|---|
| 最大化 | 四边都夹，底边到 **1020** 而不是 1023 |
| 半屏吸附 | 左上下夹到工作区，右边正常外扩 |
| 手动盖住任务栏 | 底边落到监视器这一档，夹到 1080 |
| 横跨两屏 | gap 为负，不夹（下界 0 的存在理由） |
| 普通居中窗口 | 原样返回 |
| **任务栏在左边** | 左边夹到工作区左边界 60，而不是监视器的 0 |
| reach = 0 | 不做任何事 |

变异测试：删掉工作区那一档，「最大化底边」用例立刻失败。

**实机**：反复最大化/还原 12 轮，边框矩形与工作区**逐像素相等** `(0,0,1920,1020)`，
动画中途 0.35s 采样也正确。

**全窗口回归**：用 Python 独立实现一遍 `ClampBorderToScreen`，对屏幕上每个被描边的窗口算
出期望矩形与实际比对，**9/9 一致**，其中包含使用者报告的 **Excel 最大化**场景。

## 关于 DPI 缩放

使用者要求检查不同缩放比例。结论是**几何上不受影响**：

- 修复走的全是物理像素（`GetWindowRect`、DWM 边界、`MONITORINFO`），进程 per-monitor DPI aware
- 缩放变化的实质影响是**任务栏尺寸变了**（125% 下 60px，100% 下 48px）
- 判据是相对的 `0 <= gap <= reach`，不看绝对值

单测里「底部任务栏」和「左侧任务栏」两个用例覆盖了工作区形状变化这一实质差异。
