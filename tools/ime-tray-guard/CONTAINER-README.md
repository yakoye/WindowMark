# 输入法容器研究包 0.3：仅隔离实验

**这不是可用的输入法占位保护程序。真实 Explorer 附加已经在代码中禁止。**

## 当前结果

- 本机已用用户指定的 haps03 远程桌面复现现象，用户不必再手工切换。
- 一次真实只观察诊断找到稳定容器`SystemTray.Stack / NonActivatableStack`，
  语言内容消失时该容器仍存在，宽度140→64 DIP，差76 DIP；本机100%缩放时对应76px。
- 此容器还含其它系统图标，不能未经坐标/点击验收就作为正式方案。
- 固定宽度与恢复在我们的自建测试宿主中通过；不等于真实任务栏通过。
- 随后的真实附加在订阅完成前发生Explorer的Windows.UI.Xaml.dll崩溃；当时宽度写入次数0。
  系统自行恢复Explorer，开发端没有执行重启。崩溃根因仍未证实。
- 已修正发现的COM接口跨线程封送缺口，但尚无证据证明它就是崩溃原因，不能因此宣称修复了Explorer崩溃。

## 包内工具

双击`run-container-lab.bat`只会运行以下隔离测试，约45秒，不操作用户窗口或现有输入法：

1. 29项自身进程XAML布局/恢复检查：未设置属性、数值、绑定、非法宽度及Collapsed反例。
2. 自建屏幕外、不激活的测试宿主：隐藏模拟内容，确认76 DIP空槽；正常结束时恢复原值。
3. 再建一个测试宿主，强制结束**本包自己的控制程序**，确认宿主自行恢复，再显示原内容。

输出在同目录`results`，不覆盖旧证据。程序不截图，不输入按键，不修改全局输入法设置。
`WindowMarkXamlContainerTrial.exe`只允许目标文件名为`WindowMarkXamlContainerFixture.exe`；
DLL还会再次核对宿主进程名。`--observe-taskbar`与`--reserve-taskbar`均在附加前拒绝。

不要自行把旧0.1/0.2研究文件恢复后用于Explorer。那些本地控制程序已改为`.exe.disabled`保留事故证据，未删除。
本包没有真实任务栏启用入口，也不建议在另一台电脑重复尝试原生附加。

## 尚未通过

Win10适配、多屏/DPI变化与八小时耐久。当前不安装、不发布、不合并正式功能。
