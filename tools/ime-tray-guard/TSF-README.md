# TSF 透明空项目实验 0.1

这是验证用户提出的“像 PiInput 一样向语言栏申请两个空位置”的**独立实验程序**，不是已完成的输入法保护功能。
不需要安装，不替换 WindowMark，不修改 PiInput。

## 这次要验证什么

系统接受两个私有语言栏项目后，是否真的在任务栏分配空间，以及 RDP 聚焦时是否保留。
这是固定时间注册实验，**还没有实现“原生消失才出现、原生恢复就撤销”**。
如果 Windows 不显示它们，这轮即为有用的否定证据，不用反复尝试切换全局设置。

程序不会注册/激活输入法，不处理按键，不切换语言，不使用系统 `GUID_LBI_INPUTMODE`，
不冒用 PiInput 的 CLSID，不调用 `Shell_NotifyIcon`，不注入 Explorer，不重启任何系统进程。
两个项目使用全透明图标、空文字、禁用状态；点击回调无操作。
**禁用状态不等于已经证明系统不会拦截点击，也不保证宽度与原生两个位置相同。**
通知区 WindowMark 图标是否折叠不参与此程序的注册逻辑，实际布局仍需测试。

## 在另一台电脑双击测试

请从本机桌面会话运行，不是在远程窗口内启动；无需管理员权限。

1. 准备好本地记事本/Notepad++ 和 RDP 连接窗口，不要切换现用输入法设置。
2. 双击 `run-tsf-trial.bat`，随后在10秒内点回本地编辑器。前10秒为基线。
3. 第10～55秒为注册期：在本地编辑器和 RDP 窗口间切换数次，每种状态停留约8秒。
   观察最下方**本机**任务栏，不要把远程桌面内部任务栏当成目标。
4. 第55秒自动移除。继续切换一次，确认原来的「中」「拼」/PiInput 图标、点击和中英文切换正常。
5. 等启动窗口显示 `collected-not-validated`，一般约75秒。这个状态只表示收集完成，**不是保护成功**。
6. 日志自动留在同目录 `results`。共享文件夹里不用另行传文件，告诉开发端“测好了”即可。

如出现异常：双击 `stop-tsf-trial.bat` 请求立即移除，等待主测试窗口结束。
不要用关闭控制台窗口/任务管理器结束程序代替正常停止；强制终止时尚不能保证所有系统侧状态已恢复。
若仍有问题，保留日志和截图并报告，不要反复重启 Explorer/输入法或更改设置。

## 请反馈

- 本地编辑器时是否额外出现空隙？RDP 聚焦后，左侧托盘图标是否仍向右移动？
- WindowMark 图标原本在外面还是折叠区？如果原本折叠，保持折叠测试即可，不必拖动它。
- 自动移除后，原生图标和原来输入法是否正常？有没有新图标、菜单或点击异常？
- 方便时提供任务栏局部截图；程序不截图、不抢焦点。

## 日志与隐私

`*.trial.jsonl`：注册/移除HRESULT、按阶段的管理器项目数、图标请求次数、清理确认。
`*.taskbar.jsonl`：只读 UIA 几何、固定类别、系统/显示器信息及前台进程文件名，不收集输入文本。
`*.run.json`：退出码、强制终止标记、两个EXE的SHA-256。stdout/stderr保留失败详情。
文件名唯一，不覆盖旧证据。`protection_active` 和 `visibility_verified` 始终为 false。
项目数与图标请求次数都不是实际屏幕显示证据；需要与任务栏坐标和人工观察一起判读。

## 限制

- Windows 10/11 分开验收；当前没有 Windows 10 真机通过记录。
- 未验证 Explorer 重启、多屏、系统更新、异常退出恢复、零位移、点击穿透或耐久运行。
- `SHOWNINTRAY` 标志没有受支持的任意宽度/位置保证；未绑定活动输入服务的项目可能被忽略。
- 两个私有标识为 `C67B5D22-32E8-4E7C-8826-A1C2739D4F19`、`7F935E10-6569-43A5-B238-2DE9725A61E4`；
  单会话仅允许一个实例，正常路径逆序移除并使用 GetItem 的 S_FALSE 确认不存在。
- `--stop` 只能停止同一登录会话的本实验。返回4也可能表示没有运行中的实例。
- 这不是正式发布包，不放进稳定版安装目录，也没有启用现有 WindowMark 的新功能开关。
